同一个网址，十个账号
Chrome 只记得一个

微信公众平台、几个客户的后台，它们共用一个域名。Chrome 自带的密码管理器只认站点、不认人。 SiteKey 把「标签」提到第一行，登录名退到第二行——先认出是谁，再决定填哪个。

  • 310k次 PBKDF2 迭代
  • 0个网络请求

它只解决两件事，但都是每天会撞上的

01

同域名，多账号

去重键是「注册域 + 登录名 + 匹配范围」，标签不参与去重，所以随时能改标签，不会多出一条记录。 列表按上次使用排序，常用的自然浮上来。

  • 标签第一行，登录名第二行
  • 搜索标签、账号、备注都能命中
  • 「上次」标记最近用过的那条
02

验证码框不再乱弹保存

不是所有带密码框的表单都该记。SiteKey 给每个表单打分：可见密码框 +40、用户名类字段 +30、登录语义按钮 +20、URL 语义 +10，够 60 分才认。

  • 验证码、搜索、注册改密一票否决
  • 验证码字段只从用户名候选里剔除
  • 提交并跳转后才提示，输入时不打断
03

密码留在本机

主密码经 PBKDF2-SHA256 派生 310,000 次，AES-256-GCM 加密后才落盘。解锁后的密钥只放浏览器会话内存，关掉浏览器就没了。

  • 默认 5 分钟无操作自动锁
  • 换机靠加密备份，合并而非覆盖
  • Chrome 导出的 CSV 可以先出报告再导入

怎么做的

没有框架、没有运行时依赖。Manifest V3 + TypeScript，esbuild 打四个入口，全部原生 API。

站点匹配
内置精简 Public Suffix List，智能模式下 qq.com、google.com 这类共享平台自动退化为精确 host
表单探测
递归 6 层 Shadow DOM，同域 iframe 注入，SPA 的 submit / click / keydown 都监听
存储
chrome.storage.local 只放密文，会话密钥在 storage.session，浏览器关闭即失效
多机同步
加密备份文件互相导入，按修改时间合并，删除用墓碑同步

技术栈

Manifest V3 · TypeScript · esbuild · Web Crypto
